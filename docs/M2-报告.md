# M2 报告：托盘 + 设置 + 自愈

> 日期：2026-10-19
> 状态：**已实现，自动化验证通过；托盘菜单与自启待真机点验**

---

## 1. 做了什么

### 1.1 新增项目

| 项目 | 作用 |
|---|---|
| `AutoVolume.Runtime` | 把 CLI 里的引擎循环抽出来，CLI 与 WPF 共用一份逻辑 |
| `AutoVolume.App` | WPF 托盘应用（WinExe），设置窗口按需创建 |

运行时不重复实现：CLI 的 `--diag` 现在也是订阅 Runtime 的 `Log` / `StatusChanged`。

### 1.2 功能

| 功能 | 实现 |
|---|---|
| 托盘图标 | `NotifyIcon`：状态行 / 暂停自动化 / 恢复自动化 / 立即恢复播放 / 设置 / 退出 |
| 状态提示 | 托盘文字与菜单实时显示"监听中 · 0.10"或"已暂停 QQMusic.exe" |
| 设置页 | 三个页签：音量方案、应用与控制、通用 |
| 方案编辑 | 增删方案、改名、成员增删（自动列出当前发声应用）、按设备设置音量（可关闭=首次不动） |
| 角色管理 | 每个 exe 选：不参与 / 监测源 / 受控播放器；受控播放器可选自动(SMTC)/热键，并带"测试"按钮 |
| 参数 | 互斥开关、严格/宽松、恢复延迟、有声确认、渐变、设备抑制 |
| 单实例 | `Local\AutoVolume(-dev)` + 命名事件；第二个实例唤起设置后退出 |
| 开机自启 | HKCU Run；`--autostart` 启动不弹窗；**Debug 构建不写注册表**（按 §7 规范） |
| 崩溃自愈 | `journal.json` 记录暂停对象/音量，启动时恢复并清理 |
| 退出 | 托盘退出会恢复被我们暂停的播放器 |

### 1.3 界面

设置页截图：`artifacts/tab1.png`（方案）、`artifacts/tab2.png`（应用与控制）。
深色标题栏 + 浅色内容，Segoe UI/微软雅黑，卡片式分区；无第三方 UI 库。

## 2. 实测

### 2.1 启动与单实例

| 项 | 结果 |
|---|---|
| 冷启动 | 约 1.2s 进入可工作 |
| 第二个实例 | **600ms 内退出**，第一个实例弹出设置窗口 |
| `--autostart` | 无窗口，仅托盘 |

### 2.2 崩溃自愈

手工写入 `journal.json`（暂停 QQMusic、音量 0.06→0.10）后启动：

```
检测到上次未正常退出：恢复 QQMusic.exe
自愈：恢复 QQMusic.exe
自愈：音量还原 0.100
运行时已启动
```

`journal.json` 随后被删除。

### 2.3 设置保存链路

用 UI Automation 触发「保存」：

- `config.json` 写入成功（mtime 更新）
- `运行时已启动 / 配置已重载` 出现在日志
- 窗口不关闭，右下角显示「✓ 已保存」
- 配置保留 `closeSignal`、角色、两套方案与音量值
- 中文不再被转义成 `\u97F3\u4E50`（已开 `UnsafeRelaxedJsonEscaping`）


### 2.4 体验修正（2026-10-19 02:15）

| 问题 | 修正 |
|---|---|
| 点保存后窗口直接关闭，无法继续改其他参数 | 改为**不关窗**，右下角显示绿色「✓ 已保存」，2.5 秒后淡出 |
| 暂停后找不到恢复入口 | 拆成两个独立项：**「暂停自动化」**与**「恢复自动化」**，按当前状态互相置灰；「立即恢复播放」独立，只负责恢复被我们暂停的播放器 |

### 2.5 资源占用（托盘常驻，设置窗口关闭）

| 指标 | 实测 | 目标 |
|---|---|---|
| 私有工作集（任务管理器口径） | **36.2 MB** | ≤80 MB |
| 私有字节（更严格口径） | 87 MB | — |
| CPU（单核占比） | **0.16%** | ≤0.3% 整机 |

> WPF 首次创建窗口后会保留一部分渲染资源，私有字节不回落；任务管理器显示的私有工作集仍是 36 MB，达标。

### 2.6 音量归属抖动修正（2026-10-19 02:35）

用户用 PowerToys 速览预览视频时，日志显示音量在每个预览里反复跳 3 次：

```
02:28:02.480 音量 → video = 0.160
02:28:02.863 音量 → music = 0.080     ← 383ms 后
02:28:11.361 音量 → video = 0.160
02:28:11.813 音量 → music = 0.080
```

原因：归属按"此刻峰值 > 0.01"计算。速览的音频峰值稀疏，峰值一断就落到默认（音乐）方案；
更糟的是用户此时调音量会被学习进**错误的方案**。

修正一：挂起期间归属改为"本轮响过且仍未关闭的源"，关闭后才降回音乐。VLC 测试音 18 秒无抖动；关闭后 3.4s 恢复正常。

修正二（同日）：速览预览的峰值实测只有 **0.005–0.01**，正好卡在 0.01 阈值上 →
峰值阈值改为 **0.003**（可配置 `peakThreshold`）。日志里 "有声保持到期（峰值 0.006）" 就是漏判证据。

修正三（观感）：用户反馈"声音先变大再暂停"。实测暂停确认只需 55ms，但渐变紧接着开始，
音乐尾音被一起放大。现在暂停确认后**再等 200ms**（`pauseSettleMs`）才启动渐变。日志可验证：

```
QQMusic.exe 暂停确认 55ms
音量 → video = 0.160      ← 539ms 后（55 确认 + 200 静默 + 300 渐变）
```

## 3. 已知限制

| # | 项 | 说明 |
|---|---|---|
| 1 | 开机自启未真机验证 | Debug 构建按规范不写注册表，需 Release 打包后验证 |
| 2 | 托盘菜单未自动化点击 | 需要人工点一次确认（图标在通知区域，名称 AutoVolume） |
| 3 | 设置页未做"实时预览" | 音量改动在保存后生效 |
| 4 | 新增成员默认角色=不参与 | 需要在"应用与控制"里指定角色后才会生效（有意为之，防误配） |
| 5 | 热键控制 | 设置页可选，但运行时尚未实现发送逻辑（M3/网易云时补） |
| 6 | 首次运行 | 配置不存在时自动打开设置页（本机已有配置，未实测） |

## 4. 怎么跑

```bat
scripts\dotnet.cmd run --project src\AutoVolume.App -- --dev

 :: 托盘模式（不弹设置）
scripts\dotnet.cmd run --project src\AutoVolume.App -- --dev --autostart
```

配置：`%LOCALAPPDATA%\AutoVolume-dev\config.json`
日志：`%LOCALAPPDATA%\AutoVolume-dev\logs\app.log`
