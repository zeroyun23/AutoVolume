# 新对话启动提示词

> 用法：整段复制到新对话的第一条消息。把「本次任务」一节换成你要做的事。

---

```
项目：AutoVolume —— Windows 音量自动化工具（托盘）
路径：C:\WorkBuddy_Project\Auto_Volume

先按顺序读这三份文档，再动代码：
1. docs/项目现状与交接.md   —— 架构、目录、判定规则、完成度、已知问题、后续建议
2. docs/交接文档.md         —— 需求与冻结决策 D1–D24（v1.1，只读，别改规格）
3. docs/M2-报告.md          —— 最近一次交付内容与实测数据

当前状态：
M0（spike）、M1（核心闭环）、M2（托盘 + 设置 + 崩溃自愈）已完成并真机实测。
代码约 4200 行，6 个项目，零第三方 NuGet 依赖。
开发版托盘程序可能正在运行（AutoVolume.exe --dev），改动前先确认是否要停掉。

本次任务：
【写在这里。默认建议：P0 —— Release 打包（自包含 win-x64，禁用 PublishTrimmed）、
开机自启真机验证、日志轮转。】

硬约束（违反直接打回）：
- 只调系统主音量；不用 VK_MEDIA_*；不加 SetMute 静音兜底。
- 音量方案没有优先级/互斥语义，只有 members + 每设备音量。
- 一个 exe 只能有一个角色（source / controlled）。
- AutoVolume.Core 必须是纯逻辑（不碰 COM、不碰真实时钟），便于单测。
- 不要开 PublishTrimmed：SMTC 走 WinRT 投影，裁剪后能启动但读不到媒体会话。
- 改行为先改 Engine.cs（状态机），Runtime 只负责 IO 与执行顺序。

这台机器的坑：
- 构建：scripts\dotnet.cmd build AutoVolume.sln
- 直接运行 exe 必须带 DOTNET_ROOT=C:\Users\zeroy\.dotnet（系统只有 x86 Desktop 运行时）
- 开发配置：%LOCALAPPDATA%\AutoVolume-dev\config.json
- 日志：%LOCALAPPDATA%\AutoVolume-dev\logs\app.log
- 诊断：scripts\dotnet.cmd run --project src\AutoVolume.Cli -- --dev --diag --seconds 60

验证要求：
- 任何行为改动都要有日志或实测数据，不接受"应该可以"。
- 复现工具在 spike 项目：probe / monitor / fade / smtc / keys / shot / uia。
- PowerToys 速览的 Ctrl+Space 无法用注入触发（PowerToys 以管理员运行，UIPI 拦截），
  需要用户手动按，别在这上面浪费时间。
- 看界面：spike shot "窗口标题" out.png；点按钮：spike uia "窗口" "按钮名"。

工作方式：
- 动手前先用 5 行说明你准备改哪些文件、怎么验证。
- 一次只做一件事，做完立刻验证，再进入下一件。
- 收尾时更新 docs/项目现状与交接.md 的「完成度 / 已知问题」，
  并在 .workbuddy/memory/YYYY-MM-DD.md 追加当天记录。
```

## 三种常用任务行（替换「本次任务」）

**A. 打包发布（默认）**
```
本次任务：P0
1) 用 dotnet publish -c Release -r win-x64 --self-contained 打包，禁用 PublishTrimmed；
2) 验证自包含版本能读到 SMTC、能调音量、托盘图标正常；
3) 装到固定目录并验证开机自启（HKCU Run）；
4) 加日志轮转（2MB × 3）。
```

**B. 补控制通道**
```
本次任务：P1 热键控制
1) 实现 control.method=hotkey：后台向目标窗口发送配置的组合键（SendInput，不抢焦点）；
2) 沿用现有的暂停确认（轮询 SMTC）和恢复确认；
3) 用网易云音乐实测：暂停 200ms 内生效、恢复不失败；
4) 失败时在托盘状态里标记"不可控"，不要静默。
```

**C. 先把质量补齐**
```
本次任务：P2 测试与稳定性
1) 给 Core 加 xUnit 测试：严格/宽松恢复、用户让权、音量归属（稳定模式）、关闭判定；
2) 补双源并发与设备切换的真机回归（用 spike 录 CSV）；
3) 修掉日志里高频重复的噪声事件。
```
