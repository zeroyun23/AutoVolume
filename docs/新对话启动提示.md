# 新对话启动提示词

> 用法：整段复制到新对话第一条消息，把「本次任务」换成要做的事。
> 维护：状态变化时同步本文的版本号与“当前状态”。

---

```
项目：AutoVolume —— Windows 音量自动化托盘工具
路径：C:\WorkBuddy_Project\Auto_Volume

先按顺序读，再动代码：
1. docs/项目现状与交接.md  —— 现状、进度、核心实现、已知问题、接手流程（权威）
2. docs/交接文档.md        —— 需求与冻结决策 D1–D24（规格，别改）
3. docs/M3-报告.md         —— 逐次修复与实测数据

当前状态（2026-10-23）：
- 版本 0.3.12，已发布 GitHub：https://github.com/zeroyun23/AutoVolume
- 已支持：QQ 音乐、网易云音乐（受控）；Edge、VLC、PotPlayer、Win11 媒体播放器、PowerToys 速览（声源）
- 已修复：尾音放大、渐变落点回弹、误中止、学习污染、保存死锁、图标模糊
- 未完成：强制恢复热键、hotkey 控制通道、单元测试、提权场景、真实重启点验
- 进行中：媒体播放器端到端待用户确认；退出期 CLR 卸载异常待查（见现状文档 §6.1）

本次任务：
【写在这里。例如：加一个源应用 / 修某个日志里的异常 / 发布新版本】

硬约束（违反直接打回）：
- 只调系统主音量；不用 VK_MEDIA_*；不用静音兜底。
- 会话静音只用于掐播放器尾音，暂停失败时不得使用。
- 音量方案没有优先级/互斥，只有 members + 每设备音量。
- 一个 exe 只能有一个角色（source / controlled）。
- AutoVolume.Core 必须是纯逻辑（不碰 COM、不碰真实时钟）。
- 不要开 PublishTrimmed：SMTC 会读不到；不要开单文件压缩：内存 14→90 MB。
- 改行为先改 Engine.cs；Runtime 只负责 IO 与执行顺序。

这台机器的坑：
- 构建：scripts\dotnet.cmd build AutoVolume.sln
- 发布：scripts\publish.cmd（产物 artifacts\portable\AutoVolume.exe）
- Debug exe 需 DOTNET_ROOT=C:\Users\zeroy\.dotnet
- 配置/日志：%LOCALAPPDATA%\AutoVolume\
- git push：先跑 python C:\Users\zeroy\.local\ghproxy.py，再设 HTTPS_PROXY=http://127.0.0.1:8899
  （代理跑一会儿会 502，重启即可；远端用 https://github.com:443/...）

验证要求：
- 任何行为改动都要有日志或实测数据，不接受“应该可以”。
- 工具在 spike：probe / monitor / smtc / sessmute / fade / keys / uia / shot。
- PowerToys 速览的 Ctrl+Space 无法注入（管理员进程 + UIPI），要用户手动按，别浪费时间。

工作方式：
- 动手前用 5 行说明改哪些文件、怎么验证。
- 一次只做一件事，做完立刻验证。
- 收尾更新 docs/项目现状与交接.md 的 §2.3/§3/§6，并在 .workbuddy/memory/YYYY-MM-DD.md 追加记录。
```

## 常用任务模板

**A. 加一个应用**

```
本次任务：接入 <应用名>
1) 用 spike probe / smtc list 确认进程名、AUMID、峰值；
2) 判断它当 source 还是 controlled，定关闭判据；
3) 改 Config.CreateDefault + 现有 config，必要时加 AUMID 别名；
4) 实测：播放 → 暂停 → 关闭，日志四行齐全；
5) 更新现状文档版本历史与实测结论。
```

**B. 修一个 bug**

```
本次任务：修 <现象>
1) 先复现，拿到日志时间线与 spike 数据；
2) 判断是判定逻辑（Engine）、执行时序（Runtime）还是系统端点行为；
3) 改最小面，补一条可验证日志；
4) 用 50ms 采样证明落点正确、配置未被误学习；
5) 更新 M3 报告与现状文档。
```

**C. 发布新版本**

```
本次任务：发布 0.3.x
1) 升 Version/FileVersion/AssemblyVersion；
2) scripts\publish.cmd，覆盖安装目录；
3) 真机跑一轮完整切换，确认音量落点与恢复；
4) git commit/push（走本地代理）；
5) gh release create v0.3.x <exe> <sha256>；
6) 更新现状文档与内存。
```
