## 0. 30 秒读懂

**做什么**：系统里有两类应用——
- **监测源**（Edge/VLC/PowerToys 速览）：会出声的媒体应用；
- **受控播放器**（QQ 音乐、网易云音乐）：被管理的一方。

监测源出声 → 自动暂停播放器 → 把系统音量切到该方案；源关闭 → 恢复播放器 → 还原音量。
主音量按"方案 × 输出设备"存储，用户手动调过就学习。

**现在能跑**：托盘常驻、设置页、严格/宽松两种恢复策略、崩溃自愈、单实例、三平台源实测；**Release 自包含单文件已发布、开机自启已写入 Run 键、日志已滚动**。
**还差**：真实重启后的登录启动点验、热键控制、单元测试。

| 指标 | 实测 |
|---|---|
| 空闲 CPU（托盘） | 0.16%（M2 测得）；M3 复测 0.35–0.62%，测量时机器有其他负载 |
| 私有工作集（M2 Debug） | 36.2 MB |
| 冷启动（Release，第二次起） | 0.53 s 到运行时 / 0.60 s 就绪 |

## 1. 用户视角：现在能做什么

| 场景 | 行为 |
|---|---|
| Edge 看视频 | 1.5 s 内确认有声 → 暂停 QQ → 音量切视频方案；关标签/暂停不恢复，关浏览器后 3 s 恢复 |
| VLC 播视频 | 同上；VLC 没有 SMTC，关闭判据是**进程退出** |
| PowerToys 速览（Ctrl+Space） | 同上；关闭判据是**预览窗口消失**（其 SMTC 会话不会消失） |
| 手动调音量 | 记入当前方案在当前输出设备的值 |
| 插拔耳机/切输出设备 | 抑制 5 s，重绑端点，按新端点的值执行 |
| 休眠唤醒 | 抑制 5 s，会话自动重建，不误判关闭 |
| 强杀进程 | 下次启动读 `journal.json`，恢复被暂停的播放器与音量 |
| 托盘 | 状态行、暂停/恢复自动化、立即恢复播放、设置、退出 |
| 时间参数调乱 | 通用 → 时间参数 → 「恢复默认」还原为 3 s / 1.5 s / 300 ms / 5 s，点保存生效 |
| 看不懂某个时间参数 | 点参数名右边的 `?`，弹出大白话说明（含建议值）；再点一次或点别处关闭 |

**设计上的取舍（用户已确认）**：只调系统主音量；永不用媒体键；永不用静音；不做方案优先级。

## 3. 一次循环的数据流

```
每 50/500 ms（活跃/空闲）
   │
   ├─ WasapiSessionProbe.Read()   全量枚举 3.46ms，拓扑 1s 重建；之后只读白名单 exe 的 state/peak
   ├─ SmtcService.GetSnapshotAsync()  200ms 缓存
   │
   ▼
SnapshotBuilder.BuildAsync(nowMs)
   ├─ 聚合同名 exe 的多个会话（取 Active 优先、峰值最大）
   ├─ SMTC 按 AUMID 匹配 exe
   ├─ 无 SMTC 的源按 PID 验活（进程退出后会话会残留 20s+）
   ├─ closeSignal=window 的源检查可见窗口
   ▼
Snapshot { NowMs, SmtcHealthy, Sources[], Players[] }
   │
   ▼
AutoVolumeEngine.Tick(snapshot)  ← 纯函数式：无 IO、无时钟
   ├─ 1 有声计时    峰值 > PeakThreshold，短静音按 SoundingHoldMs 保持
   ├─ 2 关闭判定    按源类型：SMTC 消失 / 进程退出 / 窗口消失
   ├─ 3 让权        用户手动播放被暂停的播放器 → 本周期不再暂停
   ├─ 4 互斥暂停    确认有声 + 播放器在播 + 未在重试冷却 → PausePlayersAction
   ├─ 5 恢复判定    严格：全部源关闭 + RestoreMs；宽松：全部静音 + RestoreMs
   ├─ 6 音量归属    稳定模式（见 §5.4）
   ▼
EngineAction[] { PausePlayersAction | ResumePlayersAction | SetVolumeAction }
   │
   ▼
AutoVolumeRuntime.ExecuteAsync  ← 有 IO、有等待
   ├─ Pause: TryPauseAsync → 轮询确认（≤300ms）→ **再等 200ms**
   ├─ Volume: VolumeFader.FadeToAsync（300ms，写 IAudioEndpointVolume）
   ├─ Resume: 先降音量，再 TryPlayAsync
   ├─ 学习：偏差 > max(0.01, 容差/2) 且 500ms 后 → 写配置
   ├─ journal：有被暂停者时写，清空时删
   └─ 状态发布（≤400ms 一次）→ 托盘/设置页
```

**进入视频的真实时间线**（`logs/settle-test.log`）：

```
t=0        峰值 > 0.003 开始计时
t=1.5s     确认有声 → PausePlayersAction
t=1.555s   SMTC 报告 Paused（日志：暂停确认 55ms）
t=1.755s   200ms 静默结束，开始渐变
t≈2.1s     渐变完成，音量 = 视频方案
```

**退出视频**：源关闭 → `PendingRestore` → 等 3 s → 先渐变到音乐方案 → 再恢复播放 → `Idle`。

## 4. 核心模块职责

### 4.1 AutoVolume.Core

| 文件 | 职责 | 关键点 |
|---|---|---|
| `Config.cs` | 配置模型 + 校验 + 默认值 + 序列化 | 一个 exe 只能有一个角色；同一 exe 不能在两个方案里；方案卷按 endpoint 存 |
| `Engine.cs` | 状态机 | 只依赖传入的 `Snapshot`，`NowMs` 由外部给；输出动作与事件字符串 |

`AutoVolumeEngine` 内部状态（改逻辑前先看懂这张表）：

| 字段 | 含义 |
|---|---|
| `_soundingSince` | exe → 首次确认有声的时间（用于 ConfirmMs） |
| `_lastSoundingAt` | exe → 最近一次瞬时峰值时间（用于 SoundingHoldMs） |
| `_episodeSources` | 本轮"响过"的源集合，用于关闭判定与稳定归属 |
| `_pausedByUs` | 我们暂停了谁（恢复责任的唯一依据） |
| `_pauseFailedAt` | 暂停失败冷却（2 s 内不重试） |
| `_smtcGoneSince` | SMTC 会话消失的起始时间（500 ms 确认） |
| `_pendingRestoreSince` | 进入恢复等待的时间 |
| `_silentSince` | 宽松模式的全静音起点 |
| `_suppressUntil` | 抑制截止时间 |
| `_userOverride` | 用户手动接管，本周期不自动暂停 |
| `_lastScheme` | 当前音量归属，防重复写 |

状态：`Idle → Suspended → PendingRestore → Restoring → Idle`。

### 4.2 AutoVolume.Audio

| 类 | 职责 | 实测要点 |
|---|---|---|
| `WasapiSessionProbe` | 枚举 render 会话、读 state/peak | 全量 3.46 ms；按 exe 白名单过滤；拓扑 1 s 重建，逐 tick 只读缓存句柄 |
| `SmtcService` | GSMTC 会话读取 + 暂停/播放 | 按 AUMID 匹配（`QQMusic.exe`、`cloudmusic.exe`、`MSEdge`、`PowerToys.Peek.UI.exe`）；`TryPauseAsync` 2 ms 返回、状态 55–204 ms 生效 |
| `EndpointVolumeController` | 主音量 scalar 读写 | `IAudioEndpointVolume`，0..1；**从不调用 SetMute**；设备切换后 `Rebind()` |
| `DeviceWatcher` | 默认设备变化 | IMMNotificationClient，回调里只置标志，不做事 |
| `WindowProbe` | 进程是否有可见顶层窗口 | 用于速览的关闭判据；过滤隐藏/零尺寸窗口 |
| `EndpointSwitcher` | 切换默认输出设备 | **当前未使用**，为后续"随应用切设备"预留 |

### 4.3 AutoVolume.Runtime

| 类 | 职责 |
|---|---|
| `SnapshotBuilder` | 合并 WASAPI + SMTC + 窗口信号；SMTC 200 ms 缓存；PID 验活缓存 500 ms；窗口状态缓存 300 ms；`ListRunningAudioApps()` 给设置页列出当前发声应用 |

## 5. 关键判定规则（改代码前必读）

### 5.1 有声

```
peak > PeakThreshold(0.003)  → 记 _lastSoundingAt
连续 1.5 s（ConfirmMs）       → 确认"有声"（可触发暂停）
峰值 ≥ FastPeakThreshold(0.02) → 只等 FastConfirmMs(600ms) 就确认
峰值归零后 1.5 s（SoundingHoldMs）内仍算在响
```

> 阈值原为 0.01，实测速览预览视频峰值只有 0.005–0.01，会漏判 → 降到 0.003。
>
> **2026-10-20 响应优化（0.3.3）**：强信号（≥0.02）走 600 ms 快通道，弱信号（速览 0.005–0.01）仍等 1.5 s，避免误触发。
> 确认后本轮发声内不再取消（`_confirmedSources`），峰值抖动不会让归属来回切。
> 设置页「通用 → 时间参数」可关闭（`fastConfirmEnabled`），关闭后一律等满 `confirmMs`。

### 5.2 关闭

| 源类型 | 判据 |
|---|---|
| 有 SMTC（Edge） | SMTC 会话消失，持续 500 ms（`SmtcGoneConfirmMs`） |
| 无 SMTC（VLC） | **进程退出**（`inactiveMeansClosedForNonSmtc=false`，Inactive 只代表暂停） |
| 进程常驻 + SMTC 残留（速览） | **无可视窗口**（`closeSignal=window`） |

> 坑：进程退出后音频会话可残留 20 s+，所以"有会话"不能推导"进程活着"，必须按 PID 验活并比对进程名防 PID 复用。

### 5.3 严格 vs 宽松

| 模式 | 恢复条件 |
|---|---|
| 严格（默认） | 本轮所有源**关闭** + 3 s |
| 宽松 | 所有源**静音** 3 s（含保持窗口） |

暂停（不关）在严格模式下**不恢复**音乐——这是刻意设计。

### 5.4 音量归属（改过一次，别再退回旧逻辑）

- **挂起期间（`_pausedByUs` 非空且未到恢复点）**：按"本轮响过、且仍未关闭的源"归属，取最近发声者。
  → 峰值短暂归零不会把音量切回音乐。
- **恢复时**：强制忽略本轮源，按"在播播放器 → 默认方案"计算，避免用视频音量恢复音乐。
- 其他情况：最近确认有声的源 → 在播播放器 → 默认方案。
- 只有 `SetVolume` 且目标变化时才写。

### 5.5 执行顺序（观感相关）

```
暂停 → 确认 Paused（轮询 ≤300ms）→ 再等 PauseSettleMs(200ms) → 渐变 FadeMs(300ms)
恢复 → 先渐变回音乐方案 → 再 TryPlayAsync
```

`pauseSettleMs` 是为了避免音乐尾音被随后的渐升一起放大（用户明确反馈过）。

### 5.6 音量学习

- 存储维度：`方案 × endpoint`，值 0..1。
- 无该设备的值 = 首次进入，**不动音量**（D2）。
- 偏差 > `max(0.01, userTolerance/2)` 且距上次写入 > `userWindowMs(500)` → 学习并写盘。
- 渐变中检测到连续两次偏差 → 判定用户拖动，中止渐变并以当前值为准。
- 注意：外部工具/其他程序改音量也会被当成"用户调整"学进去。

### 5.7 抑制（防假关闭）

| 场景 | 时长 |
|---|---|
| 默认输出设备变化 | 5 s（`DeviceSuppressMs`） |
| 休眠唤醒/时钟跳变（tick 间隔 >3 s） | 5 s |
| 音频枚举异常 | 10 s（`AudioServiceSuppressMs`） |

### 5.8 用户让权

- 引擎发现"被我们暂停的播放器又自己在播" → 本周期不再暂停它。
- 托盘「立即恢复播放」也会置 `_userOverride`，避免下一拍又被按回去。
- 源全部关闭后自动解除。

### 7.5 常见现象 → 排查

| 现象 | 先看什么 | 常见原因 |
|---|---|---|
| 视频响了但音乐没停 | 日志有没有 `源有声` | 源没配进 roles；峰值低于阈值；SMTC 匹配不上 AUMID |
| 音乐暂停了但音量没变 | 有没有 `音量 →` | 该 endpoint 没有方案值（首次不动）；目标值等于当前值 |
| 关了视频音乐不恢复 | 有没有 `全部源关闭` | 源被判成"仍打开"（closeSignal 配错、进程残留）；`_pausedByUs` 为空 |
| 音量来回跳 | `音量归属` 与 `保持到期` | 归属逻辑回退；峰值阈值过高；出现第二个源 |
| 声音先变大再暂停 | `暂停确认` 与 `音量 →` 的时间差 | `pauseSettleMs` 被改小 |
| 设置保存没生效 | `配置已重载` | 校验失败（弹窗）、写盘失败、监听的是另一个 config 目录 |

## 11. 接入一个新源应用的标准流程

以"PotPlayer"为例：

1. **配角色**：`roles["PotPlayerMini64.exe"] = "source"`；把它加进 `schemes[video].members`。
2. **定关闭判据**：
   - 有 SMTC → 默认（会话消失 500 ms）；
   - 无 SMTC 且进程独占 → `process`（默认）；
   - 进程常驻/多标签 → `closeSignal = "window"`。
3. **实测**：`spike monitor --out logs/newapp --interval 100 --seconds 60`，操作一遍"播放→暂停→关闭"，看 CSV 里的 state/peak/SMTC 变化。
4. **跑诊断**：`autovolume --dev --diag --seconds 60` 复现，确认日志里出现 `源有声`、`暂停确认`、`全部源关闭`、`恢复播放`。
5. **记录**：把结论写进 `docs/spike-report.md`，参数差异写进配置注释。
