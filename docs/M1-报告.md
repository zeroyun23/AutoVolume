## 1. 做了什么

### 1.1 项目结构

```
AutoVolume.sln
├─ src/
│  ├─ AutoVolume.Core/     配置模型、纯逻辑状态机（无 COM、无时钟依赖）
│  ├─ AutoVolume.Audio/    WASAPI interop、会话枚举/峰值、主音量、SMTC、设备监听
│  └─ AutoVolume.Cli/      M1 命令行宿主（--diag），后续由 WPF 托盘替换
└─ spike/AutoVolume.Spike/ 实测工具（monitor / probe / bench / perf / fade / sleep / switch / smtc）
```

### 1.2 能力清单

| 能力 | 实现 |
|---|---|
| 会话枚举 + 白名单 | 只缓存配置内 exe 的会话；拓扑 1s 重建 |
| 峰值检测 | 50ms 采样，>0.01 判有声，连续 1.5s 确认 + 1.5s 保持 |
| SMTC 三态 | `Playing` / `Paused` / 会话消失（500ms 确认），按 AUMID 精确匹配 |
| 窗口关闭判据 | `closeSignal: window`，用于进程常驻且 SMTC 残留的源（PowerToys 速览） |
| 暂停/恢复 | `TryPauseAsync` / `TryPlayAsync`，暂停后 300ms 内复查状态 |
| 严格模式 | 只认"本轮参与过发声的源"关闭；关闭后等 3s |
| 宽松模式 | 全部源静音 3s（含保持窗口）后恢复 |
| 音量方案 | 按 endpoint 存值；首次无值不动；用户改动即学习 |
| 音量归属 | 源优先（最近开始发声）→ 在播播放器 → 默认方案 |
| 渐变 | 8 步 / 300ms smoothstep；先降音量再恢复播放 |
| 假关闭防护 | 设备变化 5s、休眠/时钟跳变 5s、枚举失败 10s |
| 用户让权 | 手动恢复播放 → 本周期不再暂停，源全关后解除 |

### 1.3 与文档的三处实现细化（不改需求，只补判定口径）

1. **`episodeSources`**：只把"本轮响过的源"纳入关闭判定。
   否则一个从未发声的浏览器（配置源）会让严格模式永远等不到"全部关闭"。
2. **`soundingHoldMs = 1500`**：峰值归零后 1.5s 内仍算在响。
   否则视频里的短静音会让音量在方案间反复跳（实测复现过）。
3. **进程验活按 PID**：进程退出后音频会话可残留 20s+，不能用"有会话"推断"进程活着"。

## 2. 实测结果

### 2.1 严格模式完整闭环（`logs/m1-kill.log`）

| 时刻 | 事件 |
|---|---|
| 1519ms | VLC 有声确认 → 暂停 QQ 音乐 → 190ms 内变 Paused |
| 1519ms | 音量 0.140 → **0.150（video 方案）**，300ms 渐变 |
| 15633ms | 杀 VLC → 全部源关闭 |
| **18648ms** | **3.015s 后**恢复：先渐降到 0.100（music），再 `TryPlayAsync` |
| 19048ms | 状态 → IDLE |

顺序符合 D21：**先降音量，再恢复播放**。

### 2.2 严格模式：暂停/停止不恢复（`logs/m1-strict4.log`）

| 操作 | 结果 |
|---|---|
| VLC 暂停 8s | 状态保持 `Suspended`，QQ 保持 Paused，无恢复 |
| VLC 恢复播放 | 不重复暂停，音量回到 0.150 |
| VLC 停止播放（进程在） | 状态保持 `Suspended`，无恢复 |

### 2.3 宽松模式（`logs/m1-loose.log`）

VLC 暂停 → 静音 3000ms（+1.5s 保持）→ 恢复 QQ、音量回 0.100，全程 4.5s。

### 2.4 PowerToys 速览（`logs/m1-peek.log`）

| 时刻 | 事件 |
|---|---|
| 170199ms | Peek 有声（窗口可见 + 峰值 0.25 + SMTC Playing）→ 暂停 QQ，音量 0.150 |
| 194256ms | Esc 关闭速览（窗口消失）→ 判关闭 |
| 197265ms | 3.009s 后恢复：先降 0.100，再播放 |

Peek 的 SMTC 会话关闭后不会立即消失，因此单独使用 `closeSignal: window` 判据。

### 2.5 性能

| 指标 | 实测 | 目标 |
|---|---|---|
| 空闲 CPU | **0.78% 单核**（≈整机 0.05%） | ≤0.3% 整机 |
| 工作集 | **58.5 MB** | ≤80 MB |
| 私有内存 | 13.2 MB | — |
| 启动到可工作 | ~1.2s（dotnet 宿主） | ≤1.5s |

> 空闲 CPU 从 3.12% 降到 0.78%，主要靠两处：会话拓扑缓存、废弃 `GetProcessesByName`。

## 3. 怎么跑

```bat
scripts\dotnet.cmd build

# 诊断模式（默认使用 %LOCALAPPDATA%\AutoVolume-dev）
scripts\dotnet.cmd run --project src\AutoVolume.Cli -- --dev --diag

# 单独写入某方案在当前设备的音量
scripts\dotnet.cmd run --project src\AutoVolume.Cli -- --dev --set-volume video=0.15

# 宽松模式跑 60 秒
scripts\dotnet.cmd run --project src\AutoVolume.Cli -- --dev --diag --mode loose --seconds 60
```

配置：`%LOCALAPPDATA%\AutoVolume-dev\config.json`
`roles` 决定源/播放器，`schemes` 只管音量（成员 + 按 endpoint 的音量值）。

## 4. 禁止事项自检

| 约束 | 状态 |
|---|---|
| 无媒体键 | 代码中无 `VK_MEDIA_*` / `SendInput` |
| 无静音兜底 | `SetMute` 只有接口声明，从未调用 |
| 方案无优先级/互斥 | 方案只有 `members` + `volume` |
| 不全量监听 | 探针按 exe 白名单过滤 |
| 无注入/Hook/读内存 | 只用公开 COM / WinRT |
| 不改应用内音量 | 只写 `IAudioEndpointVolume` |
| 同应用不兼任 | 配置校验：一个 exe 一个角色 |
| 未开 PublishTrimmed | 未配置发布 |
