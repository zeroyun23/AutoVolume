## 1. VLC 暂停 / 停止 / 关闭

方法：VLC `--intf dummy --extraintf=http` 播放 440Hz 测试音（2s 响 / 1s 静），
HTTP 接口下发 pause/resume/stop，50ms 采样。

### 1.1 实测

| 操作 | SMTC 会话 | 音频会话 | 峰值 | 延迟 |
|---|---|---|---|---|
| 播放中 | **不存在** | `Active` | 0.2500 | — |
| 暂停 | 不存在 | `Inactive` | 0.0000 | **32ms** |
| 恢复 | 不存在 | `Active` | 0.2500 | **24ms** |
| 停止播放（进程在） | 不存在 | `Inactive` | 0.0000 | **38ms** |
| 结束进程 | 不存在 | 会话残留 ~200ms 后消失 | — | ~200ms |

**VLC 3.x 在本机完全不注册 SMTC**（整个测试期间 SMTC 列表只有 QQ 音乐和 Edge）。

### 1.2 结论

1. 对 VLC 这类无 SMTC 的源，**`Inactive` = 暂停或停止，不是关闭**。
   所以 `inactiveMeansClosedForNonSmtc` 必须为 **false**（默认已如此）。
2. 严格模式的关闭判据只能是**进程退出**：
   - 关窗口 → 进程退出 → 恢复 ✓
   - 暂停 → 进程在 → 不恢复 ✓
   - 停止播放（未关窗口）→ 进程在 → 不恢复 ✓（等价"播完没关"）
3. 若 VLC 开启"关闭到托盘"，关窗口后进程仍在 → 不会恢复。已知限制，写进 README。

## 2. 会话枚举与峰值

### 2.1 耗时

| 操作 | 平均 | p95 | 说明 |
|---|---|---|---|
| 全量枚举（7 会话） | 3.46ms | 3.99ms | 含设备激活 + 逐会话 QI |
| 缓存读取（白名单 3 会话） | 0.11–0.16ms | 0.30ms | 只读 state + peak |
| `GetProcessesByName` × 3 | **7.10ms** | 7.85ms | 空闲 CPU 的主要来源，已废弃 |
| SMTC 全量快照 | 0.023ms | 0.135ms | 比预期便宜 |

按 20Hz 读 + 1Hz 重建拓扑：约 **0.70% 单核**（Debug 构建）。

### 2.2 峰值正确性

- 测试音振幅 0.25 → 峰值稳定读到 **0.2500**；
- 静音段 → **0.0000**，会话状态仍 `Active`；
- 结论：峰值可以用来判"有声"，但**不能单次采样判定**——1 秒静音就会打断"连续有声"计时。

### 2.3 由此产生的两个实现修正

1. **拓扑缓存**：会话对象缓存 1s 重建，逐 tick 只读 state/peak。
2. **有声保持窗口**（`soundingHoldMs`，默认 1500ms）：
   峰值归零后保持 1.5s 内仍算"在响"，避免视频里的短静音导致音量在方案间反复跳。
   实测未加保持窗口时，测试音每 3 秒触发一次音量 0.15→0.10→0.15 抖动。

### 2.4 空闲 CPU（优化前后）

| 版本 | 空闲 CPU（单核占比） | 说明 |
|---|---|---|
| 优化前 | **3.12%** | 每 500ms 调 3 次 `GetProcessesByName` |
| 优化后 | **0.78%** | 仅对"有会话无 SMTC"的源按 PID 验活 |

> 0.78% 单核 ≈ 16 核整机的 0.05%。常驻内存 58.5MB（工作集）/ 13.2MB（私有）。
> 仍含 `--diag` 每秒打印开销，正式托盘模式会更低。

## 3. 音量方案与渐变

### 3.1 读写往返

```
original=0.1000 → set 0.150 → read 0.1500 → restore 0.1000
误差 0.00000（要求 <2%）
```

### 3.2 300ms 渐变

| 时间 | 回读 |
|---|---|
| 0ms | 0.1021 |
| 41ms | 0.1078 |
| 87ms | 0.1158 |
| 133ms | 0.1250 |
| 180ms | 0.1342 |
| 226ms | 0.1422 |
| 274ms | 0.1479 |
| 320ms | 0.1500 |

8 步 smoothstep，实际耗时 320ms，单调无回退，终值精确。

### 3.3 用户抢占

模拟外部写入 0.35（渐变 200ms 处）：**33ms 内检测到并中止**，保留用户值 0.35。

### 3.4 蓝牙端点的坑（重要）

默认输出是蓝牙音箱，音量写入经 AVRCP 同步，**回读滞后 50–150ms**：
- 单次偏差判定会把"还没生效"误判成"用户拖动"，导致渐变被误中止、并把错误值学进方案；
- 修正：**连续两次**偏差才中止（间隔 ~40ms）。

未解决：渐变中用户拖动会被最后几步覆盖，只有拖动持续到渐变结束后才会被学习。
300ms 窗口内概率极低，记录为已知限制。

## 4. 设备切换与休眠

### 4.1 设备切换（扬声器 → HDMI → 扬声器，IPolicyConfig 切默认端点）

| 时刻 | 默认端点 | 会话数 | VLC 状态 |
|---|---|---|---|
| 切换前 | Sound Joy | 7 | Active 0.25 |
| 切换 +0ms | X41Q | **1**（只剩 system） | 消失 |
| 切换 +136ms | X41Q | 3 | Active 0.00 |
| 切换 +352ms | X41Q | 3 | Active 0.25 |
| 切回 +111ms | Sound Joy | 7 | Inactive |
| 切回 +328ms | Sound Joy | 7 | Active 0.25 |

**结论：设备切换的会话空窗 ≤136ms，峰值恢复 ≤352ms。5s 抑制窗口有 14 倍余量。**

### 4.2 休眠 / 唤醒（Modern Standby S0）

- 实际睡眠 **79.5s**（01:11:22.257 → 01:12:41.711）；
- 唤醒后首个采样点：**7 个会话全部健在**，端点不变、主音量不变；
- SMTC 状态全程不变（QQ 音乐 Paused / Edge Paused）；
- **没有出现会话清空**，因此不会误判关闭。

结论：S0 下音频栈不重建，5s 抑制是保险而非必需；保留不影响正确性（最坏晚 5s 恢复）。

### 4.3 进程退出后会话残留（新发现）

杀 VLC 后，探针仍在默认端点上枚举到 `pid=15468` 的 `Inactive` 会话，
进程名已解析为 `unknown`，**残留超过 20 秒**。

影响：`有会话` 不能推导 `进程存活`。M1 已改为按 PID 精确验活（比对进程名，防 PID 复用），
否则严格模式永远等不到"关闭"。

## 6. PowerToys 速览（Peek）

> 版本 0.99.1.0，UI 进程 `PowerToys.Peek.UI.exe`（WinUI3，常驻约 318 MB）
> 触发方式：资源管理器选中文件 → `Ctrl+Space`

### 6.1 实测（`logs/peek-manual-*.csv`，100ms 采样）

| 状态 | SMTC 会话 | SMTC 状态 | 音频会话 | 峰值 |
|---|---|---|---|---|
| 预览播放中 | **存在**，AUMID = `PowerToys.Peek.UI.exe` | `Playing` | `Active` | 0.25 |
| 按空格暂停 | 存在 | `Paused` | `Inactive` | 0.000 |
| 继续播放 | 存在 | `Playing` | `Active` | 0.25 |
| **Esc 关闭预览** | **仍然存在** | **`Paused`** | `Inactive` | 0.000 |

关闭后 SMTC 会话**持续存在**（实测 25 秒以上，直到查询时仍在），不会消失。
Peek 进程常驻，关闭窗口后也没有可见顶层窗口。

### 6.2 结论

1. Peek **不能套用 Edge 的「SMTC 会话消失 = 关闭」**——它的会话永远是 `Paused` 挂在那里。
2. 音频会话在暂停和关闭时都是 `Inactive`，也无法区分。
3. 唯一可靠信号是**预览窗口是否存在**：
   - 打开 → 有可见顶层窗口；
   - Esc 关闭 → 无可见窗口（`WindowProbe.HasVisibleWindow(pid)` 实测 False）。
4. 因此给配置加了按 exe 的关闭判据：

```json
"closeSignal": { "PowerToys.Peek.UI.exe": "window" }
```

引擎里 `WindowOpen == false` 直接判关闭，优先级高于 SMTC / 进程判据。

### 6.3 端到端验证（`logs/m1-peek.log`，Peek 打开 tone.wav）

| 时刻 | 事件 |
|---|---|
| 170199ms | 识别 Peek 有声（win=Y、峰值 0.25、SMTC Playing）→ 暂停 QQ → 音量 0.150 |
| 194256ms | 发送 Esc 关闭速览 → `win=N` → 全部源关闭 |
| **197265ms** | **3.009s 后**恢复：先降到 0.100，再播放 QQ |
| 197650ms | 状态 → IDLE |

关闭后 SMTC 状态先短暂残留、随后变为 `Unknown`（延迟不固定，实测 >25s 仍存在过），
窗口信号是唯一即时可靠的判据。

### 6.4 实现验证

| 对象 | 可见窗口 | 探针结果 |
|---|---|---|
| Explorer（3 个窗口） | 有 | True |
| Peek（关闭状态） | 无 | False |
